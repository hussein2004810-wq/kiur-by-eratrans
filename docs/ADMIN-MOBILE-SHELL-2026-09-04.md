# إصلاح واجهة الإشراف على الهاتف

الصورة المرفقة كانت من النسخة المنشورة القديمة، بدليل ظهور بيانات الحساب الحقيقي. النسخة المنشورة لم تتغير لأن المالك كان قد اشترط عدم النشر قبل الموافقة. رابط Wi-Fi السابق كان حساب طالب تجريبيًا، لذلك لم يكن مناسبًا لفحص لوحة الإشراف.

## السبب الجذري

قواعد `.adminTabs` كانت داخل `catalog.css`. هذا الملف لا يدخل الحزمة الأساسية؛ يُحمّل عند فتح مكوّن الهيكل الأكاديمي الكسول. لذلك كانت لوحة الإشراف ترسم أزرار HTML بتنسيق المتصفح الخام، ثم تتغير بعد وصول حزمة أخرى. هذا يفسر الشكل داخل المربع الأحمر والقفزة المتأخرة.

## الإصلاح

- نُقلت واجهة الإدارة المشتركة إلى `admin-shell.css` المحمّل مع التطبيق الأساسي، مع محددات أعلى خصوصية حتى لا تستبدلها CSS الكسولة لاحقًا.
- أصبحت اللوحة على الحاسوب مساحتين: قائمة إدارة عمودية ثابتة ومحتوى القسم الحالي.
- على الهاتف تُطوى القائمة، ويظهر زر كبير باسم القسم الحالي. عند اختيار قسم تُغلق القائمة تلقائيًا ويظهر عنوان ووصف سياقيان.
- صارت عناصر القائمة بارتفاع لمس لا يقل عن 48px، مع حالة نشطة واضحة، وأدوار `tab` و`aria-selected` وحالة فتح معلنة.
- بطاقات مؤشرات الإدارة تبقى عمودين على الهاتف بدل البطاقات الطويلة جدًا، بينما يصبح المحتوى عمودًا واحدًا.
- الحركات قصيرة وتستجيب لإعداد تقليل الحركة ومفتاح المؤثرات الموجود.

## التحقق

- نجح TypeScript وبناء الإنتاج.
- اختبار جديد يثبت أن تنسيق الإدارة موجود في CSS الأولي، وليس فقط في حزمة الهيكل الأكاديمي الكسولة.
- الاختبار يفحص تسعة أقسام، قائمة الهاتف، الإغلاق بعد الاختيار، التخطيط العمودي، مؤشرات الهاتف، وتقليل الحركة.
- تعذر تشغيل الفحص المرئي الآلي لأن متصفح الفحص منع عناوين HTTP المحلية قبل فتح الصفحة. لم أتجاوز هذا القيد الأمني ولم أدّع نجاح فحص بصري لم يحدث. بقي رابط Wi-Fi بحساب مالك تجريبي ليجري المالك الفحص على هاتفه.

لم تُنشر التعديلات ولم تتصل المعاينة ببيانات الإنتاج.
